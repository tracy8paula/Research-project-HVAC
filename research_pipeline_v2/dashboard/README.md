# Live Replay Dashboard

The dashboard is an interactive prototype that replays recorded Building 59 observations as an incoming sensor stream. It is deliberately labelled as replay, not a physical sensor connection.

## Start it

From `research_pipeline_v2`:

```bash
docker compose -f docker-compose.dashboard.yml up --build
```

Open http://localhost:8051

The dashboard container mounts the local `outputs/` directory read-only. It expects:

- `outputs/processed/building59_two_stream_10min.csv`
- `outputs/models/lstm_without_spatial.pt`
- `outputs/models/baseline_scalers.json`
- selected CSV/JSON files under `outputs/metrics/`

These files are generated by the existing research pipeline and are not committed to GitHub.

## What the prototype demonstrates

1. Recorded CO2 and temperature rows are emitted at an accelerated wall-clock rate.
2. A rolling 12-sample (120-minute) input is passed to the saved validation-selected aggregate LSTM.
3. The model predicts 10, 20 and 30 minutes ahead at the configured 10-minute sampling interval.
4. As replay advances, 30-minute predictions are matched to the recorded observation at the target timestamp; running MAE is updated.
5. Model comparison, synthetic Uganda-context scenario summaries and rule-based control summaries are shown in separate tabs.

Use Start/Pause, Next reading, Reset and the playback-speed selector to demonstrate changing readings, forecast response and the evolution of observed forecast error.

## Scientific interpretation

- The stream is accelerated replay of recorded Building 59 data, not live IoT data.
- The replay forecast uses `lstm_without_spatial.pt`, the aggregate LSTM selected by validation in the saved baseline run. It is not claimed to be the best model on the historical test comparison.
- Current configured horizon is 30 minutes (three 10-minute steps), not five minutes.
- The Uganda-context scenarios are synthetic assumptions, not local measured observations.
- The historical test comparison is exploratory because the test partition was inspected before a later validation-objective correction.
- The control experiment is offline, CO2-focused and rule-based. Its fan-energy quantity is a dimensionless proxy, not kWh or measured savings.
- No physical HVAC equipment is controlled.

The server exposes `/health`, `/api/state`, `/api/step`, `/api/reset` and `/api/results`.
